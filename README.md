# 九牧马桶 → 华为智慧生活

面向九牧 `JOMOO_SMART_249734` 的本地蓝牙适配与 Home Assistant / 华为智慧生活桥接实验。两台已接入原生马桶卡片，各含 13 项服务。主卫盖圈、大小冲、泡沫盾、喷嘴清洁与停止已有用户现场确认；温度、幅度、自动除臭与落座发泡完成参数回读往返。清洗、暖风及清洗中调节已接入但尚未经人体使用验收，自清洁完整周期已结束，中途停止仍待排查。

目标是在保留原设备与九牧智联小程序的前提下，为每台马桶提供独立、可验证的控制入口。**每台物理马桶在智慧生活中只使用一张正式控制卡片，新增功能放入同一设备。**公开型号表和用户提供的照片对应 `ZD6450-SA`；兼容范围仅限本次验证的型号和功能。

## 当前路线

1. 在 Apple Silicon Mac 上运行 ARM64 Home Assistant OS 虚拟机。
2. 使用虚拟实体验证华为桥接的发现、绑定、命令路由和重启恢复。
3. Mac 上运行鉴权 BLE 网关，使用固定设备身份、新鲜状态、单次动作与持久化去重。
4. 将已验证的功能导出到智慧生活；S2、Mini、小艺与场景分别验收。

早期社区桥接使用通用开关面板；当前 OneConnect 多服务桥接已在主设备验证原生马桶页面。页面出现的控件不代表全部功能已实现。本项目与官方九牧/华为产品无隶属关系。

2026-10-27 查到华为官方 `2QBR` 对应 `ZD6450-SA-CJM305`，已有多功能马桶 Profile 和页面；其协议标为 Wi-Fi、使用 BLE 辅助配网。尚未确认现场设备是否具备相应联网模块。受限 OneConnect 多服务桥接已进入现场验证，详见兼容性调研与单卡片实验记录。

## 当前可用范围

- 两台各一张原生卡片，固定设备身份，独立路由；扩展功能与验收证据见[功能表](docs/expanded-controls.md)。
- 主卫新增功能已有分项验证，客卫复用实现但未逐项操作验收。
- 清洗和烘干要求真实落座；水压、位置、移动要求清洗状态。无证据的命令和只读字段写入拒绝执行。
- 已知设置回读比较；未知 `FA.p5.bit0` 变化单独报告，不宣称完整协议已验证。
- 同设备盖圈有界等待、动作期间误报离线和微小时钟偏差拒绝已修复；真实 BLE 延迟与偶发回读失败仍需长期观察。
- 用户 Mac 重启后的原翻盖入口已恢复；新单卡片桥接通过 HA Core 重启恢复，整机冷启动仍待验收。
- 旧桥接与四个旧子设备入口已移除，旧父网关离线卡片可在手机删除。
- 华为兼容库目前安装在 Core 容器内，更新或重建容器可能导致桥接失效。S2、Mini、小艺控制效果尚未验收。
- 小艺当前可看到设备但不能直接调用马桶模式；官方 2QBR Profile 声明 `voiceControl=0`，这属于云端产品能力限制。可行的语音替代需要华为云端开放该型号语音能力或由智慧生活场景间接触发，项目不伪造云端技能。

## 使用报告实验分支

`feat/in-card-usage-report` 提供按真实状态采样的使用记录库、每台设备独立的只读报告 API，以及日／周／月冲水和落座趋势、会话明细的原创离线 H5 模块。用 `PYTHONPATH=src python tools/preview_usage_report.py` 启动合成数据预览。

模块以同一设备卡片内的报告子页为目标；**尚未发布进智慧生活的实际九牧卡片**，需要获准的产品页面／插件宿主及数据通道。采集默认关闭，当前家庭设备未切换到本分支。完整说明见[报告模块文档](docs/in-card-usage-report.md)。

## 扫描

macOS 已开启蓝牙且授予终端蓝牙权限后，在仓库根目录执行：

```sh
mkdir -p work
swift tools/scan_jomoo.swift > work/scan.json
```

只扫描九牧广播，不连接或控制设备。扫描结果中的 macOS UUID 不等于 Linux/ESPHome 使用的蓝牙 MAC。多台设备名称相同，禁止按每次最强信号自动选择控制对象。
