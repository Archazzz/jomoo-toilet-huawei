# 单卡片马桶桥接实验

本方案已在现场完成实验父网关绑定和两台设备云端注册。用户确认主设备原生页面可打开，并在每次回到“待机中”后连续开盖、关盖、再开盖成功。第二台页面、旧卡片退出、完整 Mac 重启和更多功能仍待验收，不能标为完整可用的原生马桶集成。

## 当前证据

用户在智慧生活手动搜索未找到 ZD6450。九牧小程序设备信息显示名称 `ZD6450-SA`，该页面没有展示联网模块，不能仅凭缩写证明与官方 `ZD6450-SA-CJM305` 是同一联网版本。官方 `2QBR` Profile 声明 Wi-Fi，现场已确认的是私有 BLE 控制；官方直连仍未确认，不执行出厂重置来试错。

备用方案在一个 OneConnect 子设备内绑定多个服务。两台马桶对应两个 child，每个 child 的所有服务绑定自身同一个 HA 翻盖实体。示例见 [mapping.example.json](../deploy/oneconnect/mapping.example.json)，JSON 可由上游 YAML 解析器读取；示例默认禁用、实体为占位符。

已实现 `offSeatAction`、`toiletLidStatus`、`toiletStatus`、`seatStatus`、`toiletSetting`、`drySetting`、`washSetting`、`seatHeating` 八项服务。现阶段仅允许 `offSeatAction.action=3/4` 的翻盖操作，其余服务仅上报已知数据。未知档位不默认成零，尤其座温最高档 `100` 未建立 BLE 映射。光感夜灯、自动翻盖在此 Profile 中是只读字段，不能宣称原生页面可写。

HA 翻盖实体附带该设备的状态、动作白名单和明确过期时间，不包含蓝牙身份或网关令牌。服务读取仅接受本型号标记、可用实体和未过期状态；未知或运动中的盖圈组合不上报为稳定位置。命令按绑定实体路由，校验严格字段、数值类型和动作白名单。HA 接到命令后仍经本地网关执行新鲜状态检查、单次写入、回读和持久化去重。

## 可复现构建

下载 `research/oneconnect-source-lock.json` 中固定提交的上游源码到忽略目录，不安装浮动 main。构建器对组件的全部文件和 LICENSE 校验 SHA-256，拒绝缺失、额外或修改后的源文件；输出目录必须不存在。

```sh
python tools/build_oneconnect.py \
  --upstream work/upstream/oneconnect-95b63b78ae49 \
  --output work/staged/oneconnect-build
```

产物包含 `custom_components/jomoo_local`、`custom_components/oneconnect_bridge` 和构建摘要。保留上游许可证及本地修改说明；构建动作不接触运行中的 HA。初始映射为空，不自动注册上游默认的汽车测试模型。

对固定版本做了以下局部修改：

- 注册本项目八项服务适配器，重复 sid 立即失败。
- 在回复云端之前调用只读命令校验；未绑定、未实现、过期或禁用的命令不进入动作分发，返回非零 `errcode=1`。实际智慧生活对此错误码的呈现仍未验证。
- 合法命令的早期 ACK 仅代表接受，不代表动作完成；真实状态仍由回读更新。延长 HA 命令等待上限至 110 秒以覆盖本地网关的等待与操作上限，超时取消本次 HA 协程，不自动重试。
- 声明 `jomoo_local` 依赖，并去除默认无关子设备。

此次实验仅允许带命令预检接口的服务下发控制；不要把该构建当作其他品类的通用桥接升级。

## 已执行的隔离检查

在 HA Core 的实际 Python 环境中，将产物放在独立临时目录，运行：

```sh
python /config/check_oneconnect_build.py --build /config/jomoo_staging/oneconnect-build
```

检查脚本来自 [tools/check_oneconnect_build.py](../tools/check_oneconnect_build.py)，使用假的 HA 实体、服务和云端客户端；不会调用运行中的 HA 服务，不会发起配对或蓝牙动作。已验证模块能加载、两台各八服务映射能解析、初始映射零子设备、正确目标路由，以及不支持命令在分发前被拒绝并生成非零响应。本地另有适配器测试覆盖过期、缺失、异常类型和其他设备隔离。

### 首次原生卡片动作与工作状态修复

用户从新主设备卡片开盖，实际盖板较快打开，本地账本记录成功并通过回读；但页面持续显示“开盖中”，其他操作被禁用。初版只报告盖圈位置，缺少页面独立使用的 `toiletStatus` 服务。

现已增加该服务。停止待机的 E9 状态 01/02 还需排除自动流程、其他已知活动、故障、机构运动、冲水和发泡，才上报 `status=4`；不按计时器或请求目标假定完成。已知冲水和发泡分别上报 Profile 对应枚举，未知或冲突的活动不伪装待机。修复部署时没有发送新的机械动作。Core 重启后新父网关自动上线，无需重新配对。

用户复验第一轮开、关均正常，账本两条均为 200/verified；随后又一次开盖到达本地网关，但返回 502/UnconfirmedAction。旧日志仅保存异常类型，不能据此断言丢包、固件冷却时间或设置不符的具体原因。故新增阶段诊断，并在失败后唤醒一次优先只读刷新，缩短页面等待新状态的时间。该机制不重发失败动作，也不将读成功改写成动作成功。后续按每次回到“待机中”再操作的条件，用户确认开盖、关盖、再开盖三次均成功；本地账本分别为 200/verified，无未完成记录。此结果验证了该操作节奏下的控制流程，没有复现或解释此前的单次未确认动作，不能宣称偶发失败已根除。

### 第二台注册与旧入口迁移

在保留主设备 child key、产品定义和全部绑定不变的前提下，向同一父网关增加第二个 child；重载映射后，两台各自的注册文件均存在有效 devId。没有发送客卫机械指令。客卫新卡片页面尚待用户确认，不能把云端注册成功等同于手机端验收。

旧集成保持停用，其绑定与备份保留。HA 当前未发现自动化、场景或脚本实体，但这不证明华为云端没有旧卡片的场景引用。旧集成的移除实体流程会实际删除云端子设备，且需要重新加载原生 SDK；迁移时应明确核对旧“翻盖”卡片和场景引用，不能删除供新卡片共用的 HA 翻盖实体。

## 后续验收

1. 两套桥接使用 UDP 5683。已备份原集成和 `.storage`，通过 HA 停用旧集成后仍有原生库监听端口，需要重启 Core 才释放。之后创建新网关，用户完成绑定，父网关上线。原身份数据保留以便恢复。
2. 两台 `2QBR` 子设备注册均已返回云端凭据，用户确认主设备原生页面能正常打开。子设备数量传感器只统计配置项数，本次另外核对了实际注册凭据，未将计划数量误当注册成功。具体服务的双向控制仍需逐项验收。
3. 核对离线呈现、状态过期与动作错误提示。适配器不报假状态，但云端缓存与页面显示需实测；不能据此宣称云端离线已处理。
4. 首次机械动作仅使用主设备和已验证翻盖。更多功能须逐项完成实机验收；温度、冲水、清洗、发泡等尚未开放。
5. 新卡片验收完成后再迁移原入口与场景引用，最终每台物理设备只保留一张正式卡片。旧绑定数据在迁移期间保留以便恢复；不能用 HA 分组冒充华为卡片已合并。

实验期间原桥接已停用，绑定与备份保留。若新卡片验证失败，停用新桥接、确认发现端口释放后恢复旧桥接；不能同时启动两套发现服务。S2、Mini、远程、断网和长时间稳定性另行验收。
