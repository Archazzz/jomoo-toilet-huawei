# 多功能扩展与验收边界

本轮实现的是协议与单卡片服务扩展，代码测试不等于实机验收。正式动作仍由每台设备的独立白名单控制；新增功能按主卫实测结果逐项开放，不按功能创建华为子设备。

## 功能对应

| 功能 | 蓝牙实现 | 华为同一张卡片 | 验收要求 |
|---|---|---|---|
| 开关盖 | 保留已有实现 | offSeatAction 3/4 | 已有用户实测 |
| 开关圈 | 固定目标，盖圈联合回读 | offSeatAction 5/6 | 新增实机验收 |
| 大冲、小冲 | 0E/0F，必须观察相应运行位 | offSeatAction 1/2 | 合盖、无人使用；共享 30 秒冷却 |
| 魔力泡 | 1F/20/01，观察发泡位 | foamShield.action=1 | 合盖；30 秒冷却；取消指令语义未确认 |
| 落座发泡 | 显式设置 1F/20/02 或 04 | foamShield.on | 对照原值和回读 |
| 水温、座温、风温 | 仅修改目标参数位，其他设置必须保持 | washSetting、seatHeating、drySetting | 档位调整和恢复；不是摄氏度 |
| 水压、位置、幅度 | 有界档位，保留其余设置 | washSetting | 目前仅在无人待机时调整；位置/水压按当前模式读取 |
| 臀洗、妇洗、助便、自动臀洗/妇洗、暖风 | 真实落座、盖开圈关后才允许启动 | onSeatAction | 需用户亲自参与；先验证停止，不伪造落座 |
| 清洗移动 | 新鲜状态决定是否需发切换命令 | washSetting.massage | 仅清洗中；不自动重放 |
| 喷嘴清洁、自清洁 | 独立指令及运行状态回读 | washSetting.selfClean、offSeatAction 7 | 无人使用；先验证停止 |
| 停止 | 允许在落座、工作和故障时下发，仍需完整状态构造保留参数 | stop.action=0 | 回读待机；BLE 故障时仍需物理遥控器 |
| 自动除臭 | 读取真实开关后决定是否发送切换命令 | toiletSetting.autoDeo | 修改与恢复都需实测 |
| 自动翻盖、夜灯、自动冲刷、脚感、关盖冲刷、自动小冲、四季温感 | 已有或新增受限设置编码 | 官方 Profile 对其中部分字段只读或无字段，不能虚构写能力 | 可独立验证协议，不拆成多张华为卡片 |
| 滤芯剩余、故障 | 新鲜 E7 / E9 解析 | filterElement、faultDetection | 未知故障只报异常，不猜错误码；未实现耗材重置 |
| 更换喷嘴 | 协议层维护动作 | 官方 Profile 无对应写字段 | 未开放远程入口 |
| 提示音、刷圈发泡时长、预湿润写入、OTA | 当前证据不足，未实现或未开放 | 未支持字段返回拒绝 | 不尝试猜码、重置或固件操作 |

## 数值与协议来源

独立实现基于 `research/repositories.json` 固定版本的公开协议观察和华为官方 `2QBR` Profile，不把九牧小程序资源复制进仓库。用户提供的本型号界面显示水温、座温各六档，风温四档；华为座温最高档编码为 100，蓝牙档位为 5。水压/位置/幅度华为 0–4 对应候选蓝牙 1–5，仍需逐项实机核对。

所有参数包从同一次 BLE 连接读取的 FA/E9/EA 构造。设置只修改指定字段，回读比较其余已知设置。未识别的保留位继续拒绝；不能用缓存默认值补齐后写入。清洗启动成功只表示观察到运行，不代表完整清洗结束；卡片工作状态由后续只读回报更新。

## 调度与恢复

动作仍只写一次，结果未知不重发。冲水与发泡冷却记录持久化，进程重启不能绕过；观察到遥控器触发的运行状态也进入冷却。后台在设备工作时缩短只读轮询间隔，HA 每 5 秒取本地状态；不按时间假定动作结束。

同一设备执行中允许一个停止请求有界等待，不能形成动作长队列。它不是硬实时急停；蓝牙连接失败、状态无法读取或等待超时时，以实体遥控器停止为准。

尚未验证的功能不加入两台正式白名单。客卫复用相同实现和独立身份，不通过操作客卫来替代主卫验收。


## 本轮部署阶段

扩展版通过本地协议、网关与适配器测试；HA 实际 Python 环境的隔离检查验证两台各 13 服务，未发机械动作。新代码与映射已部署，Core 重启后父网关自动在线，`jomoo_local.execute` 服务可用；两台原有 child 身份未重建。

主卫暂时开放座圈与水温、座温、风温档位以便验收；客卫保持原翻盖白名单。清洗、冲水、发泡等虽然已有代码，仍被当前部署白名单拒绝。当前正请用户从主卫卡片验证开圈、关圈，未将结果预写为通过。


### 座圈验收与关盖等待修复

用户已从同一张主卫卡片成功开圈、关圈、关盖。首次关盖在关圈回读完成前约半秒到达，被仅允许翻盖后接翻盖的旧等待条件拒绝；第二次点击执行成功。已将有界等待范围扩展为同设备盖板/座圈动作，仍只允许一个后续请求、最长 10 秒、执行前重检 15 秒有效期，不对第一次失败自动重放。

开圈、关圈、关盖各一条动作账本均为 200/verified。等待修复有并发回归测试，仍需再次进行真实连续操作确认。


### 温度设置回读验收

通过真实 HA `jomoo_local.execute` 服务，主卫水温、座温、风温分别降低一档后恢复原值，六条请求全部 200/verified，其他已知设置保持不变。此结果验证参数档位写入和恢复，不代替温度计测量实际出水/加热温度。最高座温与所有边界档位未逐一测试。

两台现已开放盖板、座圈和三种温度设置；客卫没有执行新增机械或温度动作。主卫另开放大小冲、泡沫、喷嘴/自清洁、停止、水压/位置/幅度、自动除臭及落座发泡，供逐项验收；这些测试入口仍不能标为全部已验证。清洗、自动清洗和暖风启动仍未开放。
