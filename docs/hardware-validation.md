## 状态校验边界

本型号控制使用同一次连接中新查询的 FA、E9、EA，不拼接历史缓存。动作只写一次，之后仅查询结果；超时、断连或回读不符均不自动重发。检测到落座、工作中、机构运动或设备故障等状态时拒绝机械动作。

回读必须满足目标盖/圈位置和已知设置一致。FA 第 5 字节的 bit 0（从 0 编号）在动作及被动状态中均观察到变化，上游也将其标为未知；当前保留为 `uninterpreted_changes: ["FA.p5.bit0"]`，不赋予含义，也不当作已知设置变化。

因此返回的验证范围是 `target_and_known_settings`，**不能解读为所有未知字段与隐藏设置都已证明不变**。对其他尚未解释的控制配置位采取拒绝控制，不盲目覆盖。E2 未返回，温度等依赖该类设置的适配未完成。

## 华为桥接和重启

修复 ARM64 依赖并改到华为设备所在子网后，鸿蒙智慧生活添加了“智控网关”和验证 A/B。用户切到 A 关、B 开，HA 收到独立状态；一次 HA Core 重启后，桥接身份不变，用户确认在线、无需重新绑定，再切到 A 开、B 关，HA 正确收到。

真实翻盖实体随后加入同一桥接白名单，不替换测试开关。第一次手机开盖到达 HA，但被网关以蓝牙忙碌拒绝，账本无动作记录。调整调度后，新的手机开盖、关盖请求均执行成功，用户与回读分别确认。

当前控制优先于尚未开始的轮询；无线锁等待上限已调整为 10 秒，同设备翻盖允许一次新请求等待，具体边界见[调度说明](local-gateway.md)。请求等待后再次检查 15 秒有效期。BLE 全局串行，两个房间始终使用各自固定身份。完整操作还有 85 秒总超时，HA 请求超时 95 秒；通常数秒完成并不代表所有请求保证在 15 秒内完成。

交互运行的网关进程退出后重新启动，两台重新只读成功且均回报盖关闭，动作账本仍仅有先前开/关两条记录；未产生新的控制记录。此验证不涉及 macOS 独立后台授权，也不是整机重启。

尚未通过：断电冷启动、72 小时稳定性、远程/断网、小艺/S2/Mini、iPhone。此前网关依赖交互环境，用户重启后已转为独立后台运行，见下节。HA Core 更新/容器重建还会丢失手工补装的 gcompat，见[部署说明](deployment.md)。


## 用户重启 Mac 后的检查

同日用户完成 Mac 重启后，HAOS 虚拟机和独立 Jomoo Gateway LaunchAgent 均已运行，HA HTTP 页面返回成功。原生 app 的蓝牙授权状态为允许，主卫、客卫均持续读取成功。华为绑定文件和当前容器的兼容库仍存在；动作账本保持上次两条控制记录。

HA 到网关的 HTTP 请求却被断开。macOS 防火墙的应用列表和系统设置均显示 Jomoo Gateway 为“阻止传入连接”；底层同时出现 SO_KEEPALIVE 的 Invalid argument。临时停用 TCP 保活后连接仍被断开，因此已撤回该改动，不将其当作修复。

用户随后确认放行。通过系统设置移除并保存构建目录的旧阻止规则，再添加当前安装 app 的允许规则并保存；系统防火墙保持开启。Mac 和 HA Core 容器分别访问网关成功，两台均返回在线、盖关闭；没有修改 TCP 保活代码。用户随后确认通过原智慧生活入口开盖、关盖均可用，未重新创建或绑定网关。此次恢复包含一次人工防火墙规则修复，不等同于全程无干预的冷启动验收。蓝牙授权已跨过此前障碍，但无法仅凭重启后的结果断言授权生效的具体原因。


## 动作期间短暂离线的修复

重启后的手机控制复验中，用户报告偶尔在开启时提示断连。对应最近六条主卫请求账本全部返回成功和已验证，读取日志持续成功；HA 历史记录则在部分动作中短暂进入 `unavailable`，随后约 8–10 秒恢复 on/off。

代码在开始动作时清空状态并设置不可用，导致正常执行中的设备被桥接成离线。已改为在有效期内保留最后确认的状态和原采样时间，另设 `busy` 标记；不把请求的目标位置提前当成真实位置。成功后用新回读更新，动作未确认、读取失败或缓存过期仍不可用。新增成功/失败两类并发状态测试，检查等待中不闪离线、不伪造目标、不延长时间戳及另一台状态隔离。

此修改针对已找到的动作期间误报，不能证明所有断连都由同一原因引起。后续仍需记录实际蓝牙失败与远处设备覆盖问题。动作日志现包含时间和动作类型，便于与 HA 历史对齐，不记录令牌或完整设备身份。

## 2026-10-27 连续操作与扩展功能

用户反馈误报断连已基本消失，仍有 3–8 秒响应和部分开关回弹。日志显示部分关盖请求在前一次开盖回读结束前到达，被旧调度拒绝为 HTTP 409；两次拒绝分别发生在前次完成前约 0.8 秒和 2.2 秒。这提供了软件调度原因，不能据此断言所有问题都已排除或全部归因于蓝牙距离。

已部署同设备一次有界翻盖等待、近期固定身份发现对象复用和分阶段计时。两次主设备只读刷新均命中发现对象，读取约 2.24 和 2.32 秒；两台保持可读取。该结果不替代用户手机端动作与延迟验收。

自动翻盖、光感夜灯新增设置仅完成代码和测试，尚未向现场发送设置命令。现有两台的动作白名单仍只有翻盖，未增加按功能拆分的华为卡片。官方直连型号与备用多服务桥接详见[调研](research.md)。
