# 家庭报告中心接入调研

日期：2026-10-27。问题：将马桶、床、环境、能耗等报告汇集到我们自己的卡片，是否可以避开九牧现有产品页面的开发授权。

## 结论

**可以把九牧页面授权从方案中移除，但无法因此自动获得智慧生活自定义页面的发布权，也无法自动取得其他厂商的报告数据。**

自建“家庭报告中心”在技术上可行。我们已经拥有马桶报告采集与页面模块，可以把它作为中心内的一个栏目。中心使用自己的页面、设备命名与本地统计，不必修改九牧的 2QBR 页面。各实物设备仍各用一张控制卡片，报告中心是统一查看入口，不再为每个统计项创建虚拟设备。

如果中心必须出现在正式智慧生活设备列表，就需要华为认可的产品身份、页面宿主、认证与发布通道。仅将现有“智控网关”改名，或给 HA 增加统计实体，并不能替换它在华为侧的界面。

## 三个独立条件

| 条件 | 自建中心能否解决 | 证据与现状 |
|---|---|---|
| 修改九牧现有页面的权限 | 可以避开 | 中心是独立原创页面，不修改 2QBR 页面 |
| 把中心放进正式智慧生活的资格与入口 | 仍需华为流程 | 产品创建、企业伙伴准入、页面审核；NEXT 插件还有专门发布流程 |
| 获取各产品的历史与完整报告 | 逐设备确认 | 本地状态可自算；厂商云端报告、睡眠评分等不因聚合页面存在而开放 |

## 官方入口核对

### 自有产品／网关页面

华为[《成为合作伙伴》][1]正文说明：“本章节仅适用于企业账号，不适用于个人账号。”操作流程包含“必须完成企业实名认证”，以及申请 HarmonyOS Connect 生态产品或解决方案合作计划、审批和签署协议。页面更新于 2026-08-21。

这意味着公开的标准接入流程不是注册一个普通个人华为账号即可上传任意卡片。没有登录核验本用户的企业资质或账户能力，也不把这一页扩大成所有特殊合作渠道均不可能开放。

[《创建产品》][2]允许标准／自定义开发方案，但明确要求选择自定义方案前与品类产品经理确认是否支持 HarmonyOS Connect 认证；缺少品类时可反馈需求。云云对接仅向受邀合作伙伴开放。页面更新于 2026-08-21。

“家庭报告中心／数据网关”只是拟议产品定位，尚未确认平台有可直接使用的对应品类，不能把“其他”品类当作任意聚合应用的通行证。将 Mac/HA 作为实际聚合后端并不自动满足产品接入要求。

现有桥接上游默认网关产品是 `ZG37`。[其公开 Profile][3]仍指向厂商 `ZG37/h5_001/index.html`，服务为添加子设备、网络检测、信号、场景操作、网络信息和升级，没有任意自定义报告地址字段。当前上游 `ProductSpec`／映射支持产品身份和服务映射，没有页面上传或 H5 URL 替换能力。故现有网关不能直接充当已获授权的通用网页容器。

这部分结论来自公开 Profile 和已锁定上游代码；未宣称已穷举所有华为产品或私有接口。

### 智慧生活 Debug 版：有明确的验证路径

新核对到[《使用智慧生活 App 调测 H5 功能》][4]，更新于 2026-04-08。其完整步骤包括：

1. 登录 Device Partner，在“产品开发 > 集成开发”下载智慧生活 App Debug 版。
2. 在 Debug 版选择“认证沙箱”，添加待调测设备。
3. 手机和运行 H5 的电脑连接同一局域网。
4. 在“我的 > 设置 > 关于 > H5 地址设置”填入本地地址。
5. 设备页 URL 访问重定向到这个调测地址，进行页面与设备联调。
6. 正式发布前仍需打包上传、提交 UI 审核。

因此，**在正式发布之前，确实有机会先在智慧生活调试宿主内验证报告中心**；这比只在普通浏览器预览更接近最终目标。

但它不是已证实可长期使用的正式入口：下载依赖平台访问，环境为认证沙箱，页面描述为设备页 URL 重定向，未保证只覆盖一张指定卡片。没有验证现有正式绑定是否在沙箱可见、当前鸿蒙机型能否安装此调试版，或 NEXT 是否兼容这一 H5 调试方案。后续验证应使用独立测试环境，不把正式家庭绑定直接切换到沙箱，也不先假定改一个 URL 就能完成接入。

[《HarmonyOS NEXT 插件发布》][5]则要求将未签名 HSP 经 CEPM 交华为接口人，由华为合入智慧生活 NEXT 并发布。它与普通浏览器网页或传统 H5 调试并不是同一种交付。

### 独立网页、HA 页面或鸿蒙应用入口

我们自己托管的家庭报告网页／HA 页面可以自由扩展，使用自己能够读取的数据即可，无需修改九牧页面，也无需智慧生活页面发布。但入口在浏览器或 HA，不能称为已经进入智慧生活。

独立鸿蒙应用／桌面服务卡片也可作为后续宿主方向，但这是另一套应用开发、签名和分发事项，不自动成为智慧生活设备卡片。华为[原子化服务概述][6]将其描述为“具有独立入口、免安装”的应用形态；本文所查 HarmonyOS Connect 原子化服务指南仍面向合作伙伴，不是公开的任意网页注入开关。

| 路线 | 可做自定义总览 | 在正式智慧生活中 | 适合当前用途 |
|---|---|---|---|
| 本地网页／HA 总览 | 可以 | 不在 | 快速形成有用的家庭报告中心 |
| 智慧生活 Debug + 本地 H5 | 文档支持调测 | 不等于正式版 | 验证真实宿主、身份和数据通道，需平台及设备条件 |
| 自有产品／网关自定义页面 | 获批后可以 | 有条件可以 | 最接近用户目标，先核实企业伙伴、品类与发布渠道 |
| 修改现有 ZG37／2QBR 页面 | 当前无对应权限 | 现有入口在 | 改名或 HA 映射不能解决页面权限 |
| 独立鸿蒙应用／服务卡片 | 可另行开发 | 不自动进入 | 入口可接受放在系统桌面时再评估 |

## 数据能够汇总到什么程度

| 数据源 | 可行程度 | 需要补齐的工作 |
|---|---|---|
| 九牧两台马桶 | 已有采集实现，未在生产启用 | 实际运行覆盖率、漏采及断连验收；统计“已记录冲水／落座”，不冒充排便识别 |
| 已能进入 HA 的温湿度、空气、插座等状态 | 有对应集成和可用测量值时可以统计 | 逐设备确认接入、单位、历史保留和传感器；仅有开关状态不能推算实际耗电量 |
| 慕思完整睡眠报告／评分 | 尚未确认可读取 | 官方接口、账号授权或可用本地协议；不能仅凭智慧生活能显示就认定 HA 能读取 |
| 其他仅在智慧生活可见的设备 | 未自动接入 | 当前 OneConnect 路线主要把 HA 能力导出到华为，不是把所有华为设备数据导入 HA |

作为补充证据，慕思 `2QN4` 的公开 H5 资源中存在厂商云域名引用；这只能说明有厂商服务依赖线索，不能据此声称已经找到或获准调用睡眠报告 API。没有尝试越过账号权限读取报告。

华为[《云端服务申请（仅部分品类支持）》][7]明确：近期历史记录、统计数据需要申请对应功能权限；申请针对产品物模型中的功能／属性，由审核人员审核。支持品类列表含“其他”，但不意味着自动获准或取得其他厂商产品的历史。若统计由我们自己的本地库生成，这部分华为云历史权限可以不作为本地统计引擎的依赖；正式页面如何安全获取本地数据仍需宿主联调。

## 建议的后续关卡

1. 以“家庭报告中心”为统一前端，现有马桶模块作为第一个栏目；每个来源独立展示采集状态、更新时间与缺失原因。睡眠、环境、能耗在取得真实数据后再加入，不先制造完整家庭报告的假象。
2. 先核实是否有可使用的企业合作伙伴账号，以及平台是否接受家庭数据聚合／网关这类产品。没有平台入口时，继续扩大前端并不会解决卡片接入。
3. 若具备平台能力，优先验证 Debug 版 + 独立测试设备 + 本地只读 H5，确认当前手机兼容、父卡片身份、鉴权、返回导航和重定向范围，再讨论正式发布。
4. 将家庭设备清单分成“已有本地原始数据”“需接 HA”“只有厂商报告”三类。前两类可自行统计；第三类另查厂商接口和授权。
5. 中心的认证应单独管理，不把马桶控制令牌当作全屋报告访问令牌，也不把家庭事件库推到公开仓库。

本轮只调研并更新文档，没有更换现有设备卡片、申请企业资格、接受合作协议、切换手机环境或启用新的采集。
