# 如厕使用报告可行性调研

调研日期：2026-10-27。范围为现有两台 249734 马桶、Mac 蓝牙网关、HA 和智慧生活单卡片桥接。本次只研究与制定方案，没有启动新的使用记录采集，没有改变运行中的卡片或触发设备动作。

> 后续实现已转向用户要求的卡片内部报告，见[实验分支与模块说明](in-card-usage-report.md)。下文保留调研时的路线比较，HA 仪表盘不作为本轮交付目标。

## 结论

每日冲水、落座、清洗记录及趋势图可以自行实现。当前九牧原生卡片不能通过增加 HA 实体或修改 OneConnect 映射直接插入报告页。建议先以本地事件库和 HA 报告页实现，保留智慧生活里每台一张原有控制卡片；如果“必须在现有华为卡片内部”是硬要求，则需要解决产品页面的开发与发布权限，不能承诺仅靠本地代码完成。

“落座且使用过臀洗”可以作为明确的组合指标；它不是已识别的排便次数。现有已解析协议没有排便识别、便便性状、体重或使用者身份数据，不生成健康评分或个人诊断。用户所说慕思睡眠报告可作为展示形式参考，本次没有核验其具体型号、传感器和算法，不宣称两种硬件具备相同测量能力。

## 卡片扩展调查

直接读取华为公开的 [2QBR Profile][1]，其 `uiType=H5`，页面入口为 `2QBR/h5_001/index.html`。16 项官方服务中包含盖圈、落座、工作状态、设置、滤芯、故障及升级，没有日冲水计数、如厕会话、历史报告或自定义报告链接字段。

核对 [H5 入口][2]及其加载的 `app.961c348a05d5bfcd668e.js`，路由包含首页、设置、除臭、泡沫、滤芯、故障、固件升级和状态页，未发现使用报告路由或图表入口。包中的 `history` 主要用于浏览器返回导航，不能当作设备历史 API。资源仅用于核对行为，没有复制进项目发布代码。

固定版本 OneConnect 的 `ProductSpec`、映射解析和注册实现选择产品身份及服务，没有替换厂商 H5 URL／上传插件的配置。增加一个自定义计数服务不会让既有 H5 自动长出图表；在 HA 建图也不会同步成为智慧生活里的页面。

华为[线下 H5 准备工作][3]明确要求先“创建产品并完成产品定义（包括软硬件定义与物模型定义）”，在智能硬件合作伙伴平台进入对应产品开发，提交 UX 设计审核。还要求 H5 资源打包、正式包去掉调试代码。文档中的“H5 开发包中不允许引入外部链接”位于离线资源要求，不能把它扩大解释成所有 API 网络访问均被禁止；但也没有据此获得把任意本地报告网址塞进九牧卡片的能力。

现有九牧产品页面由厂商平台管理，本项目没有该产品的页面管理权限。自行创建新产品、自定义页面并完成正式发布是另一路线，需验证账号资格、品类、物模型、审核、H5／HarmonyOS NEXT 插件适配及数据接口。即使新产品获批，也不能假定现有 2QBR 卡片可原位替换而无需迁移绑定。调试版预览不等于正式智慧生活安装后可用。

| 路线 | 图表能力 | 能否满足现有卡片内展示 | 当前判断 |
|---|---|---|---|
| 修改现有 HA / OneConnect 映射 | 可以增加后端数据 | 不会修改厂商页面 | 不可作为插入图表方案 |
| HA 中做设备使用报告 | 日／周／月图表、记录明细、筛选 | 入口在 HA，不在华为卡片 | 可实现，推荐先做 |
| 原创手机网页或 PWA | 布局和交互可自定义 | 当前卡片没有已验证跳转入口 | 可实现独立入口，但不声称嵌入成功 |
| 厂商更新页面或授权产品开发 | 能定制原生卡片内报告 | 有机会，取决于平台发布与身份 | 条件性路线，权限和审核待核实 |

报告页不需要在华为设备列表再创建若干“冲水计数”虚拟卡片；仍坚持一个物理马桶一张正式控制卡片。

## 统计口径

| 指标 | 定义 | 可以知道与不知道的部分 |
|---|---|---|
| 大冲／小冲次数 | 对应运行位由已知关闭变为开启，记一次观察到的冲水事件 | 不等于按钮点击数；漏采的完整短周期无法补算 |
| 落座次数 | 去抖后的未落座→落座开启一次使用会话 | 马桶按房间区分，不自动识别人 |
| 落座时长 | 同会话中落座开始到离座的估算时长 | 开始、结束都在相邻采样之间；显示估算或范围 |
| 落座＋臀洗次数 | 同一落座会话内至少一次已观察到臀洗运行，该会话计 1 次 | 同一人反复启停臀洗不增加这个组合次数 |
| 臀洗／妇洗／助便启动次数 | 分别统计观察到的模式启动，含明确自动模式标签 | 自动流程阶段切换不新建如厕会话；断连后的运行状态不当作新启动 |
| 暖风／泡沫使用次数 | 按相应运行状态的起点记录 | 泡沫可由落座自动触发，不推断来源为按钮 |
| 日、周趋势与明细 | 房间、会话、时间、时长、清洗类型、关联冲水、完整性 | 日期按 Asia/Shanghai；次数归启动日，跨日时长按日切分 |

第一版可展示“今日已记录落座”“其中使用臀洗”“观察到的大冲／小冲”、7／30 天柱状图、落座时长分布和单次明细。无数据时显示“未采集”，有采样缺口时显示“记录不完整”，不能用 0 伪装未使用。

将“落座＋臀洗”称为“疑似排便”仍有歧义：有人排便后不用臀洗，也有人仅清洁。建议名称写“落座并使用臀洗”，另允许用户主动标注排便，只有明确标注才形成排便记录。不自动把房间或清洗类型关联到家庭成员。

## 当前数据为何不够

网关 SQLite 目前仅有 `commands` 和 `cooldowns` 表，控制请求去重账本并非完整使用历史。轮询状态保存在内存；普通日志主要记录读取是否成功及动作结果。HA 有落座实体及状态属性，但本次未审核它的实际历史保留和完整性，不能假定能回填全部历史。

统计不得用 HTTP 200 数量代替动作次数：`already_satisfied` 不代表新增动作；重复 ID 返回原结果；`not_sent` 不能计数；`unconfirmed` 可能执行也可能未执行，不能计作成功或直接当作未发生。一次有回读证据的控制与紧随其后的运行位变化要合并为同一事件。

目前待机轮询为每轮两台串行读取，再等 60 秒；工作期间等 3 秒，但完整周期还包括两台的连接与读取时间。因此并非每台严格 3 秒采一次。HA 每 5 秒读取的只是本地缓存，并不增加实际蓝牙采样频率。普通落座待机目前也不会单凭 `seated=true` 缩短周期。

遥控器、九牧小程序、离座自动冲水和自清洁收尾冲水，可能完全发生在两次轮询间。只增加 HA 统计传感器无法解决这种漏记。当前公开字段中尚未找到可补偿漏采的设备累计冲水计数或带时间戳历史记录；不能断言所有未解析协议都没有，但现在不可依赖它们。

## 推荐实现

1. **先验证采集覆盖。** 只读研究已连接时设备是否主动推送落座／冲水／清洗变化，是否需要主动查询；同时评估两台长期连接与九牧小程序抢连接的影响。当前短连接能收到通知不等于已证明持续推送。增加轮询也需测试控制延迟，不为统计让控制更慢。若短冲水仍漏采，页面只能称“已记录次数”，或再评估独立近端采集器／额外传感器；不能预先宣称能精确统计所有来源。
2. **在网关新增独立事件库。** 所有成功取得的新鲜状态（轮询、控制前读取、控制后回读）进入同一观察入口，记录设备键、采样时间、启动周期、状态、命令关联和质量；明确未发送的拒绝不生成动作。事件、会话和聚合结果使用稳定 ID 去重、事务持久化、规则版本，控制账本不改作统计表。
3. **处理缺口和重启。** 不能把 `unknown`／`unavailable` 当离座。启动时若已落座，记起点未知的会话，不从开机时间声称完整时长；重连时若冲水位已开，标记边界不完整，不假定又冲了一次。连续观察同一运行只计一次；跨长缺口不猜测合并或精确时长。由最后明确状态与首次新状态给边界区间；短暂落座抖动按待验证阈值合并，不使用任意健康阈值。
4. **HA 展示。** 同一 HA 设备下增加事件型记录和累计计数传感器；持久化单调累计值配合适当的 `state_class` 供日／周图表使用，时长单独统计。报告卡片读取本地聚合数据，点击日期查看会话，不创建华为虚拟子设备。计数与会话数据库为数据源，HA 缓存丢失可重建图表。
5. **验收再开放长期记录。** 对照人工真值覆盖手机、实体遥控器、自动冲水、连续两次冲水、未执行请求、断连恢复、重启、中途进程退出、跨午夜和两台并行；报告命中、漏记、重复和时间误差，不预写可靠率。

HA 官方 [History Stats][4] 可统计状态持续时间和出现次数，但 `count` 统计所选时间段中出现过的目标状态，开始时已处于目标状态也会计入，不等于严格的启动边沿次数。其历史长度受 Recorder 保留期限制，不能直接用于跨月精确会话计数。

HA [Statistics graph][5] 支持统计传感器图表；官方文档说明每 5 分钟及每小时生成统计，小时统计长期保留。这适合展示累计计数增量，不能替代原始如厕会话。详细记录保存期限与累计统计分别配置，初版可选明细 90 天、日聚合长期保留；所有真实家庭记录只放本机私有存储，支持按日期删除和本地导出，不进入 GitHub。

## 实施顺序与验收门槛

先做持续观察小实验和事件状态机，再做一页日／周／月报告。第一版优先指标为“已记录冲水”“落座会话”“落座且臀洗”，同时显示采集缺口；无需先购买硬件。若要求覆盖全部自动和遥控器短事件，就必须先验证持续采集能力，不能用漂亮图表掩盖漏采。

“现有智慧生活卡片内直接看报告”单独作为平台可行性关卡。当前已找到官方开发流程，但没有九牧产品权限，也没有完成自有产品申请或插件调测，因此这部分仍未打通。本轮不把独立 HA 报告页说成已经满足卡片内展示。
